# 2026-10-20 — macro-map

## Goal
M1 terrain pipeline, first step: a YAML polygon macro map in world metres, validated, rasterised to a region grid and checked for full coverage.

## What was done
- Core: `Point2D`, `Polygon` (simple-polygon validation, area, bounds, half-open `Contains`).
- Data: `biome` and `world` content types, regions inside maps, new codes `DATA015`-`DATA017`, region-to-biome reference check, loader and database extended, shared property parsing moved to `ParserSupport`.
- Gen: `MacroRasterizer` and `RegionField` with `TERR001`-`TERR005`; generator ID and version; checksum.
- CLI: `macro-map`.
- Sample content: three biomes, one world of 20,480 m with three regions (placeholders).
- Swept the codebase for undocumented null-forgiving operators (CLAUDE.md section 8.2) and documented each.
- Docs: ADR 0006, biome and world references, validators, Gen system doc, two how-tos, glossary, known issues 17-22.

## Decisions made
- [0006 Macro map format](../decisions/0006-macro-map-format.md). The developer chose: YAML polygons, biome records, explicit ocean regions.
- Implementation choices recorded in the ADR: multi-polygon regions, mandatory total coverage, cell-centre ownership with a half-open rule, 20,480 m world (80 chunks of 256 m = 320 cells of 64 m).

## Problems encountered and how they were solved
- A symmetric bow-tie polygon has signed area exactly 0, so the zero-area check reported it with the wrong message. Reordered: self-intersection is tested first, and an up-front "all vertices collinear" check gives the zero-area message. Caught by tests.
- My hand-worked oracle for the shipped world had an off-by-one (186 instead of 188 land columns per axis: the largest centre below 6000 m is 5,984, not 5,920). The rasteriser was right; the test caught my arithmetic and the oracle derivation was corrected and confirmed by a second, independent example.
- My first "add a region" how-to example would have failed with `TERR003`. Rewrote it as a tested carve-out and ran both the right and wrong versions.
- Markdown tables in `validators.md` had been split by blank lines from earlier edits; repaired and checked across all docs.

## Tests added
- Core `PolygonTests` (15): validity rules, concave containment, tiling by shared edges and vertices.
- Data: `MacroMapParserTests`, `BiomeParserTests`, four more loader tests.
- Gen: `MacroRasterizerTests` (16): coverage, gaps, overlaps, borders through cell centres, multi-polygon, determinism, analytic oracle for the shipped world, golden checksum.
- Whole solution: 211 tests, 0 warnings.
